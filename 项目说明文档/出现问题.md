# DDR RAG 问题记录

本文件记录实施过程中出现的问题、已确认原因、解决方案与验证结果，供后续排查和交接使用。

## 2026-09-23 18:27:00（Asia/Shanghai）— HybridChunker 首次导入耗时过长

- 状态：已解决。
- 问题现象：首次进程启动时，`from docling.chunking import HybridChunker` 超过普通终端的 60 秒等待窗口，看似卡住。
- 影响范围：延迟了 HybridChunker 的启动诊断；原始 PDF、解析结果、向量索引和在线 API 均未受影响。
- 已确认原因：HybridChunker 导入链会加载 `transformers 5.12.1`；该版本首次导入会通过 `importlib.metadata` 扫描当前 Python 的已安装分发包，在本机耗时约 90 秒。随后 HybridChunker 可成功导入，不是 Docling 版本不兼容或死锁。
- 解决方案：在获准的项目 `.venv` 中以可持续运行的本地进程完成首次导入；无需升级、降级或替换 Docling。
- 验证结果：`docling 2.107.0`、`docling-core 2.85.0`、`semchunk 3.2.5`、`transformers 5.12.1` 与 `pandas 3.0.0` 环境下，HybridChunker 成功完成三份文档切分。

## 2026-09-23 18:35:00（Asia/Shanghai）— 本地 OpenAI Tokenizer 依赖缺失

- 状态：已解决。
- 问题现象：切分前的依赖检查提示 `ModuleNotFoundError: No module named 'tiktoken'`。
- 影响范围：无法以未来 `text-embedding-3-small` 对应的本地 Token 口径实现约 600 Token 的切分和复算验证。
- 已确认原因：项目原有 `pyproject.toml` 未显式声明 `tiktoken`，且项目 `.venv` 中未安装该包。
- 解决方案：将 `tiktoken>=0.8,<1` 加入项目依赖，并安装 `tiktoken 0.14.0` 到项目 `.venv`；该库只在本地执行 Token 计数，不调用 OpenAI API。
- 验证结果：所有输出 Chunk 的 `token_count` 均由 `text-embedding-3-small` 对应的本地编码复算一致。

## 2026-09-23 18:47:00（Asia/Shanghai）— 重复表头导致单个 Hybrid Chunk 超过 600 Token

- 状态：已解决。
- 问题现象：瑞芯微文档的一个 HybridChunker 表格块因重复表头达到 619 Token，超过配置的 600 Token 目标。
- 影响范围：首次真实资料切分在原子写入前中止，未生成半成品 `chunks.jsonl`。
- 已确认原因：HybridChunker 优先保持表格结构和重复表头；对于不可再按结构拆开的长表格项，最终序列化文本可能略超出其 Token 预算。
- 解决方案：保留 HybridChunker 作为主切分器；仅当其最终上下文化文本超限时，使用本地字符安全的最终保护拆分，并在每个子块重复章节上下文、保留原块的页码和全部资料元数据。
- 验证结果：三份资料重新切分后共 795 块，实际最大 Token 数均为 600；瑞芯微、TI、NXP 的 P95 分别为 595、593、598。

## 2026-09-23 20:15（Asia/Shanghai）— 项目环境复用的 PyTorch 为 CPU 版本

- 状态：已解决。
- 问题现象：项目 `.venv` 可导入 `torch 2.10.0+cpu`，但 `torch.version.cuda` 为 `None`、`torch.cuda.is_available()` 为 `False`，无法使用本机 RTX 4060 执行 BGE-M3 GPU 向量化。

- 后续动作：保留 D 盘 wheel 缓存以便环境重建；除非用户明确授权，不进入 Qdrant 建库。

## 2026-09-23 21:45（Asia/Shanghai）— FP16 向量归一化精度未满足最终校验

- 状态：已解决。
- 问题现象：BGE-M3 已在 RTX 4060 上完成首次向量生成，但 `validate_embedding_artifact` 报告“Normalized embedding vectors do not all have unit norm”。
- 影响范围：首次生成的向量产物未通过验收，不能作为后续索引输入；未创建 Qdrant、未调用 API、未修改 Chunk 或原始 PDF。
- 已确认原因：模型在 FP16 推理模式下输出，原实现先以 FP16 做 L2 归一化、后转 float32 保存，量化误差可能超出 `1e-4` 的严格单位范数校验。
- 诊断或解决方案：保持模型 FP16 推理以节省显存，但在 GPU 上先将 CLS dense 输出转换为 float32，再执行 L2 归一化并保存；随后使用 `embed --replace` 重建并验证全部向量。模型文件已在 D 盘缓存，不会重新下载。
- 验证结果：修正后完整自动测试为 `13 passed`；独立验收通过：795 个 `float32` 向量，形状 `(795, 1024)`，无 NaN/Inf，ID 映射唯一，范数范围为 `0.9999998807907104–1.0000001192092896`，符合 `1e-4` 单位范数容差。
- 后续动作：该向量产物可作为后续 Qdrant Local 建库输入；未经用户明确授权不建库。
