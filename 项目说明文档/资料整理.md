## Qdrant Hybrid Search

地址：[Qdrant Hybrid Search 官方文档](https://qdrant.tech/documentation/search/text-search/hybrid-search/)

内容摘要：

Qdrant 的混合检索可以在一次查询中结合 Dense vector（语义相似度检索）和 Sparse vector（关键词、词项匹配检索），再使用 RRF（Reciprocal Rank Fusion）按照排名融合多路结果。

Qdrant 支持在同一个 Point 中保存多个命名向量，例如一个 dense 向量和一个 sparse 向量。查询时可以通过 `prefetch` 分别执行语义检索和词法检索，再使用 RRF 合并结果。这样既能处理“DDR5 初始化失败”这类语义查询，也能处理型号、寄存器名、料号和错误码等精确关键词查询。检索阈值需要结合数据集和模型实际调优。

## Docling CLI 格式说明

地址：[Docling CLI 官方文档](https://docling-project.github.io/docling/reference/cli/)

内容摘要：

Docling CLI 支持输出 Markdown、JSON、YAML、HTML、Text、DocTags、Chunks 和 LaTeX 等格式。默认输出 Markdown；`--to json` 输出结构化 JSON；`--to chunks` 直接输出文档切块；`--chunks-type` 支持 `hybrid` 和 `hierarchical`；`--chunks-max-tokens` 可设置最大 Token 数；`--chunks-tokenizer` 可指定 Hybrid Chunker 使用的 Tokenizer。CLI 还支持表格提取、OCR、页面范围和 CPU/GPU 设备选项。

## Docling Hybrid Chunker

地址：[Docling 文档切分说明](https://docling-project.github.io/docling/concepts/chunking/)

内容摘要：

`HybridChunker` 先根据文档层级进行初始切分，再根据 Tokenizer 和 Token 限制进行调整。它会拆分超过限制的 Chunk，并在标题和表格标题相同的情况下尝试合并过小的相邻 Chunk；相邻 Chunk 合并默认开启，也可以通过 `merge_peers` 关闭。使用与后续 Embedding 模型匹配的 Tokenizer，有助于使切分长度符合模型实际输入限制。

对于跨多个 Chunk 的表格，Hybrid Chunker 默认会重复表头，使每个 Chunk 单独使用时仍保留表格上下文。对于特别宽的表格，可以在必要时省略表头，以避免超过 Token 限制。

## Docling RAG 示例

地址：[Docling RAG with LangChain 示例](https://docling-project.github.io/docling/_generated/examples/rag_langchain/)

内容摘要：

示例展示了如何使用 Hugging Face Tokenizer、`HybridChunker` 和 `DoclingLoader` 加载文档并生成 RAG Chunk。根据导出类型，可以得到文档 Chunk 或 Markdown；如果使用 Markdown，还可以继续使用 Markdown 标题切分器处理。示例强调，Hybrid Chunker 的 Tokenizer 应尽量与后续 Embedding 模型匹配。

## RAG 原始论文

地址：[RAG 原始论文：Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)

内容摘要：

论文将知识分为两类：参数化记忆（parametric memory），即保存在预训练生成模型参数中的知识；非参数化记忆（non-parametric memory），即保存在外部可检索知识库中的知识。论文中的 RAG 模型使用预训练序列到序列模型作为参数化记忆，并使用外部 Wikipedia dense vector index 作为非参数化记忆，通过神经检索器找到相关文本，再结合检索结果生成答案。

论文指出，相比只依赖模型参数的方式，RAG 能够生成更加具体、多样且事实性更强的答案。对本项目而言，外部 DDR 知识库可以独立更新，回答时还能返回对应文档、章节和页码，因此更容易追溯和验证。
