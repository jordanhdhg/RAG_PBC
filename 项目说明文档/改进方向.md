## 1. 改善 PPT 图文提取

### 已发现的问题

部分幻灯片的关键信息位于图片、图形、特殊文本框或当前解析器未完整提取的内容中。现有 Chunk 可能只有标题或截断文字，造成“原幻灯片中存在，但 RAG 没有可引用正文”。阶段 5 中的通道 De-Skew、差分信号摆幅/功耗、共模噪声抵消和 3.5 dB 预加重示例均受到这一限制。

### 影响

- 检索可能正确定位到幻灯片，但回答器仍因正文不足而拒答。
- 如果强迫回答，容易形成无法回查原文的结论。
- PPT 资料的实际利用率低于 PDF 文本资料。

### 建议方向

1. 自动识别正文过短、只有标题或图形占主导的幻灯片。
2. 复查 PowerPoint 原生文本框、组合对象和图表文字。
3. 对必要页面执行 OCR，并区分“原生文本”“OCR 文本”和“人工审核补充文本”。
4. 所有补充文本保留原幻灯片号、提取方式、审核状态和来源哈希。
5. 先构建独立试验产物，通过抽样和回归后再决定是否重建正式 V2 索引。

### 建议验收

- 目标幻灯片的关键文字可回查，且不会把 OCR 推断伪装为原始正文。
- `V2_SI_ANS_04`、`V2_SI_ANS_06`、`V2_CROSS_02` 对应证据得到改善。
- 原 90 题、本地领域隔离和引用定位不退化。

## 2. 建立独立的语义要点完整度验收

### 已发现的问题

阶段 5 自动来源覆盖为 35/36，但人工逐题核对后，只有 29/36 道可回答题完整覆盖本题两条预期要点，另有 7/36 道部分覆盖。引用正确只能证明答案使用了正确来源，不能证明必要条件、例外和数值都已表达。

### 影响

- 单看引用通过率会高估答案完整度。
- 对时序、电气安全、模式限制等工程问题，漏掉一个条件也可能影响实际判断。

### 建议方向

1. 将检索命中、来源引用、拒答正确性和语义要点覆盖分成独立指标。
2. 语义结果至少区分：完整覆盖、部分覆盖、未覆盖、与证据矛盾、无依据扩展。
3. 初期以人工复核为准；如引入自动裁判，不让回答模型直接给自己的答案打分。
4. 自动语义复核优先使用本地模型或独立评审模型，并保留人工抽检。
5. 评测报告同时展示自动指标和人工指标，不互相替代。

### 建议验收

- 每条预期要点都有独立状态及可审计理由。
- 自动引用率不再被表述成事实完整率。
- 当前 7 道部分覆盖题能作为固定回归样本。

## 3. 将查询别名迁移到版本化领域术语表

### 已发现的问题

阶段 5 为改善中英文工程表达差异，在 `query_scope.py` 中加入了 ODT、dropout、return current、上电初始化等通用术语扩展。当前实现有效，但继续直接扩充代码会逐渐难以维护，也可能产生查询漂移或跨领域歧义。

### 影响

- 术语增加后，很难追踪某个别名为何加入、适用于哪个领域。
- 同一个英文词可能在内存、信号完整性和其他领域具有不同含义。
- 修改术语需要修改 Python 代码，审查和版本比较不直观。

### 建议方向

1. 建立版本化 YAML 术语表，记录标准概念、中英文别名、缩写、领域、主题和来源。
2. 只允许通过审核的术语进入正式查询扩展，不进行无监督自动收录。
3. 对容易歧义的术语增加领域约束和负向测试。
4. 保留术语变更历史，并为每项扩展设置检索回归题。
5. 查询扩展结果进入路由/检索调试输出，便于解释排名变化。

### 建议验收

- 当前已有术语映射迁移后检索指标不退化。
- 非相关领域不会因别名扩展而混入结果。
- 新增或撤销术语不需要修改核心检索代码。

## 4. 改进多子问题回答结构

### 已发现的问题

部分题目同时询问定义、作用、适用条件和例外。模型可能正确回答主体内容，却漏掉一个已有证据支持的细节，例如 CKE 电平门限、ODT 的用途或 Burst Stop 限制。

### 影响

- 答案看起来正确，但不能完整覆盖用户的全部问题。
- 工程限制和例外更容易被遗漏。

### 建议方向

1. 在提示词中要求先识别并覆盖每个子问题。
2. 对每个子问题分别给出“有证据回答”或“证据不足”的状态。
3. 允许局部拒答，避免一个子问题证据不足时整题拒答或强行推断。
4. 控制答案长度，避免为了逐项回答而重复堆砌证据。
5. 使用当前 7 道部分覆盖题验证改进效果，并检查是否增加无依据扩展。

### 建议验收

- 子问题覆盖率提高，同时伪造引用、无依据推断和请求重试不增加。
- 输出结构对普通单问句仍保持简洁。
- API Token 和费用变化得到单独记录。

## 5. 统一离线检索、在线引用和人工语义验收口径

### 已发现的问题

阶段 4 对跨领域题主要检查预期领域覆盖，阶段 5 前置门则统一检查全部精确来源锚点，导致阶段 4 已通过、阶段 5 开始时又以 30/36 的统一 all-anchor 指标暂停。两种指标都有意义，但定义和使用阶段不同。

### 影响

- 容易把统计口径变化误解为索引退化。
- 不同报告之间难以直接比较。
- 阶段门可能在执行时才暴露未提前声明的要求。

### 建议方向

1. 固定并分别命名：领域覆盖率、题级全锚点命中率、锚点召回率、来源引用率、拒答率和语义完整率。
2. 每个阶段在开始前声明主门槛和诊断指标。
3. 阶段 4 即输出后续在线阶段需要的全部指标，但不把本地结果冒充在线结果。
4. 报告保存题集版本、Top-K、证据上限、配置和索引标识，保证可比较性。

### 建议验收

- 相同数据和参数在不同报告中得到相同指标定义。
- 阶段门失败时能直接指出是哪一个指标，而不是笼统显示“评测失败”。
- 历史报告仍保留原口径说明，不回写或覆盖。

## 6. 为未审核培训知识补充更权威来源

### 已发现的问题

当前信号完整性资料为 2009 年培训材料，来源身份已正确标记为 `unverified_note`。其中包含抖动、差分测量、预加重和反射等有用知识，但不应被当作原厂规范或通用标准要求。

### 影响

- 内容可能受年代、接口、仪器或培训语境限制。
- 关键结论如果只有未审核材料支持，工程可信度有限。
- 即使文本提取完整，也不能替代适用器件和接口的正式资料。

### 建议方向

1. 优先寻找芯片厂商应用笔记、测量仪器厂商指南、接口规范和当前器件资料。
2. 新资料先做来源、版本、适用范围、保密性和重复性审查，再决定是否登记。
3. 保留培训材料作为解释性或辅助证据，不删除历史来源。
4. 回答中并列不同来源的适用条件，权威资料与未审核经验不得混写。

### 建议验收

- 重要信号完整性结论至少有一份更权威、可追溯的来源支持。
- 新来源不会未经用户批准自动入库或覆盖现有资料。
- 来源身份和适用范围在检索、引用和回答中继续完整显示。

## 推荐优先顺序

1. PPT 图文提取。
2. 语义要点完整度验收。
3. 版本化领域术语表。
4. 多子问题回答结构。
5. 统一评测口径。
6. 补充更权威来源。

前两项对当前实际答案质量影响最大。是否把这些内容正式设为 V2 后续阶段、是否允许重建索引或调用 API，均需用户另行明确决定。
