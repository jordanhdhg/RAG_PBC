# 通用硬件 RAG V2 筛选条件速查

更新时间：2026-10-07（Asia/Shanghai）  
用途：在日常使用 RAG 时，快速选择合适的领域、主题、型号、内存类型、接口和资料范围。

## 1. 先理解筛选与 Chunk

V2 知识库分为四层：

    V2 知识库
      └─ 文档：10 份资料
          └─ Chunk：1,825 段可检索正文
              └─ 元数据：领域、主题、型号、DDR 类型、接口、章节、页码等

Chunk 是系统按章节和语义从长文档自动切出的正文小段，每段最多约 600 Token。每一个 Chunk 都保留文档名称和版本、章节标题、PDF 页码或幻灯片号、领域、主题、适用型号、接口和 DDR 类型等可追溯信息。

不需要记忆或手工输入内部 Chunk ID。提高命中率的正确方法是：

- 在问题中写出准确的型号、接口、信号、DDR 类型和工程术语。
- 在确定范围时使用 --domain、--part、--memory-type、--interface 等参数。
- 精确术语优先使用关键词检索；概念性问题优先使用混合检索。
- 不要叠加不确定的筛选条件；错误筛选会排除本来正确的证据。

推荐问法结构：

    型号 + 对象或信号 + 具体工程动作或约束

例如：

    GW3A-20 外接 DDR3 时，时钟差分对的拓扑、阻抗和等长要求是什么？

而不是：

    这个怎么布线？

## 2. 基础命令模板

每个新的 PowerShell 窗口先执行：

    Set-Location D:\pcb\AI_PCB
    . .\scripts\use_d312_env.ps1
    $RagPython = ".\.venv-d312\Scripts\python.exe"

纯本地检索模板：

    & $RagPython -m ddr_rag search "问题" --config config.hardware-v2.yaml --domain 领域 --limit 6 --format text

在线生成答案模板：

    & $RagPython -m ddr_rag ask "问题" --config config.hardware-v2-online.yaml --domain 领域 --limit 6 --format text

说明：

- search 始终只做本地检索，即使误用了在线 YAML 也不会调用 DeepSeek。
- 只有 ask 加上 config.hardware-v2-online.yaml 才会调用 DeepSeek。
- 在线 ask 会发送问题和最多 6 条本地检索证据正文及来源元数据。
- 默认 config.yaml 是冻结 DDR RAG V1.2；使用通用硬件 V2 时必须显式传入 V2 配置。

## 3. 领域：--domain

| 中文领域 | 参数值 | 适合的问题 |
|---|---|---|
| 内存与 DDR | memory | DDR2/3/4/5、LPDDR、DDR 走线、端接、拓扑、DDR 电源 |
| 高速接口 | high_speed_interface | USB、SATA、PCIe、HDMI、SGMII、CSI |
| 电源管理 | power_management | LDO、电源轨、上电时序、去耦、滤波、电源完整性 |
| 电气安规 | electrical_safety | 电气间隙、爬电距离、绝缘、高压 PCB |
| 信号完整性 | signal_integrity | 阻抗、端接、眼图、抖动、反射、差分信号 |
| 通用硬件 | hardware_general | 原理图、Bank、I/O、管脚、晶振、配置模式、PCB 通用设计 |

示例：

    --domain memory
    --domain power_management
    --domain signal_integrity

跨领域问题必须重复指定领域：

    & $RagPython -m ddr_rag search "电源噪声如何影响高速信号质量？" --config config.hardware-v2.yaml --domain power_management --domain signal_integrity --limit 6

跨领域时，--limit 不能小于领域数量。

如果 route 返回 clarification_required，说明系统不能唯一确定领域。此时补充 --domain；它不表示资料没有入库。

## 6. 检索模式：--mode

| 模式 | 参数 | 适合场景 |
|---|---|---|
| 混合检索 | --mode hybrid | 默认推荐；结合语义与关键词。 |
| 语义检索 | --mode dense | 中英文术语不一致、以概念描述问题时。 |
| 关键词检索 | --mode sparse | 精确型号、引脚、寄存器、数值和术语检索时。 |

示例：

    & $RagPython -m ddr_rag search "VCCX VCCIO" --config config.hardware-v2.yaml --domain power_management --mode sparse --limit 6

    & $RagPython -m ddr_rag search "稳压器输入接近输出时为什么不能维持稳定输出？" --config config.hardware-v2.yaml --domain power_management --mode dense --limit 6

不写 --mode 时，系统默认使用 hybrid。

## 10. 使用原则和边界

- 优先用自然语言把型号、对象和目标写清楚，再使用筛选条件缩小范围。
- --domain 是最有价值的筛选条件；确定型号时加 --part，确定 DDR 类型时加 --memory-type。
- 资料中出现的准确章节词、器件名、信号名和缩写会帮助检索，例如 VCCX、VCCIO、ODT、VTT、PDN、Bank、LVDS、参考平面。
- 不需要在问题中刻意写“Chunk 名称”，也不需要记内部 Chunk ID。
- 每轮结果中的 [C1]、[C2] 是临时证据编号，只对该轮查询有效。
- 重要数值、管脚、封装、时序、阻抗和安规结论必须回看原始资料；RAG 用于定位和汇总，不代替工程签核。
- 信号完整性培训 PPT 被标记为未审核工程经验，不能替代原厂资料或标准。
