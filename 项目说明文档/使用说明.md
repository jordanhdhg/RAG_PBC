# 通用硬件 RAG V2 使用说明

更新时间：2026-10-07（Asia/Shanghai）  
适用对象：日常查询本项目已入库硬件资料的使用者。  
当前知识库：10 份资料、1,825 个可检索 Chunk；包含高云 TN662-1.3.2 与 UG206-1.9.3。

## 1. 程序怎样使用

当前程序通过 PowerShell 命令行（CLI）使用。它暂时没有网页界面，也不是持续运行的聊天窗口；每提出一个问题，执行一条命令。

日常只需要使用三条命令：

- route：判断问题属于哪个硬件领域；不检索、不调用 API。
- search：只在本机检索资料和原文证据；不调用 API。
- ask：先本机检索，再将问题和有限证据交给 DeepSeek 组织成答案。

不需要重新安装环境、重建索引、启动 Qdrant 服务或 Docker。日常提问不要执行 parse、chunk、embed、index、bm25 或 ingest；这些是资料入库和维护命令，可能改写正式派生产物。

推荐工作流：

    进入项目目录
      ↓
    加载 D 盘独立环境
      ↓
    route 判断领域
      ↓
    search 检查原文证据
      ↓
    确认资料可靠
      ↓
    确有必要时才 ask 生成答案

先检索、后生成的好处是：可以先看到系统到底依据了哪些资料，再决定是否向在线模型发送有限证据。

## 2. 每次打开 PowerShell 后的准备

### 2.1 进入项目目录

打开 PowerShell 后执行：

    Set-Location D:\pcb\AI_PCB

### 2.2 加载项目 D 盘独立环境

执行：

    . .\scripts\use_d312_env.ps1

开头是“点、空格、脚本路径”。成功后会显示：

    D-local project environment is ready: D:\pcb\AI_PCB\.venv-d312

这个脚本仅对当前 PowerShell 窗口生效，作用是：

- 使用项目 D 盘中的独立 Python 3.12 环境。
- 将临时文件、pip、uv、Hugging Face 和 tiktoken 缓存固定在项目 D 盘目录。
- 设置 UTF-8 中文输出。
- 不修改系统 PATH、注册表、.env 或旧 .venv。

### 2.3 建议强制本地模型离线运行

如果本次只想检索本地资料，再执行：

    $env:HF_HUB_OFFLINE = "1"
    $env:TRANSFORMERS_OFFLINE = "1"

这两个变量只在当前窗口生效，用于阻止模型组件联网检查或下载。

### 2.4 设置简短命令变量

执行：

    $RagPython = ".\.venv-d312\Scripts\python.exe"

之后统一使用：

    & $RagPython -m ddr_rag ...

其中 & 是 PowerShell 的“执行该路径”符号。

当前 use_d312_env.ps1 不会把命令行脚本目录加入 PATH，因此不建议直接输入 ddr-rag。请稳定使用 & $RagPython -m ddr_rag，或使用完整路径 .\.venv-d312\Scripts\python.exe -m ddr_rag。

### 2.5 仅检查程序是否正常

    & $RagPython -m ddr_rag --help

日常使用时应该能看到 route、search 和 ask 三个命令。

## 3. 配置文件：必须明确选择 V2

本项目保留了旧 DDR RAG V1.2 基线，因此不要依赖默认 config.yaml。日常查询通用硬件 V2 时，必须显式传入 V2 配置：

| 使用目的 | 配置文件 | 是否联网 |
|---|---|---|
| 本地路由和检索 | config.hardware-v2.yaml | 否 |
| DeepSeek 在线回答 | config.hardware-v2-online.yaml | 是 |

两份 V2 配置的知识库、资料、Chunk、向量、Qdrant、BM25 和分类路径相同；功能性差别是离线配置的 generation.enabled 为 false，在线配置的 generation.enabled 为 true。

## 4. 第一步：用 route 判断检索范围

route 只判断查询范围：

- 不加载 BGE-M3 模型。
- 不搜索 Qdrant 或 BM25。
- 不调用 DeepSeek。
- 不需要 API Key。
- 不向外部发送问题或资料。

示例：

    & $RagPython -m ddr_rag route "LDO 的压差电压是什么？" --config config.hardware-v2.yaml --format text

可能返回：

    status: resolved
    domains: power_management
    topics: ldo
    routing_source: automatic

这表示程序把问题识别为电源管理领域中的 LDO 问题。

### 4.1 出现 clarification_required 时怎么办

route 是确定性规则路由，不会擅自把可能跨领域的问题扩大搜索。例如下面的问题能够识别型号 GW2A，但仅靠型号不能确定你问的是电源、DDR、通用硬件还是信号完整性：

    & $RagPython -m ddr_rag route "GW2A 的 VCCX 与 VCCIO 上电顺序和滤波要求是什么？" --config config.hardware-v2.yaml --format text

此时会返回 status: clarification_required。请补充领域：

    & $RagPython -m ddr_rag route "GW2A 的 VCCX 与 VCCIO 上电顺序和滤波要求是什么？" --config config.hardware-v2.yaml --domain power_management --format text

这不表示资料没有入库，而是系统在防止跨领域误检。

## 5. 第二步：只在本机搜索原文证据

search 是日常最推荐的命令。它使用本地 BGE-M3 语义向量、本地 Qdrant 和本地 BM25 检索，不调用 DeepSeek，不需要 API Key，也不发送问题或资料到外部。

### 5.1 高云 GW2A 电源要求

    & $RagPython -m ddr_rag search "GW2A 的 VCCX 与 VCCIO 上电顺序和滤波要求是什么？" --config config.hardware-v2.yaml --domain power_management --part GW2A --limit 6 --format text

当前库中该查询会命中高云 UG206-1.9.3 的“电源指标”“上电时序”和“电源滤波”等章节，并返回相应 PDF 页码和原文。

### 5.2 高云 DDR3 设计

    & $RagPython -m ddr_rag search "GW3A-20 连接 DDR3 时 Bank 和 I/O 应该如何分配？" --config config.hardware-v2.yaml --domain memory --memory-type DDR3 --part GW3A-20 --limit 6 --format text

### 5.3 DDR4 时钟布线

    & $RagPython -m ddr_rag search "DDR4 时钟差分对的拓扑、阻抗和等长要求是什么？" --config config.hardware-v2.yaml --domain memory --memory-type DDR4 --limit 6 --format text

### 5.4 LDO 问题

    & $RagPython -m ddr_rag search "LDO 的压差电压、负载调整率和稳定性应该如何判断？" --config config.hardware-v2.yaml --domain power_management --topic ldo --limit 6 --format text

### 5.5 高速接口问题

    & $RagPython -m ddr_rag search "PCIe 差分对的阻抗、过孔和参考平面需要注意什么？" --config config.hardware-v2.yaml --domain high_speed_interface --interface pcie --limit 6 --format text

### 5.6 电气安规问题

    & $RagPython -m ddr_rag search "高压 PCB 的电气间隙和爬电距离受哪些因素影响？" --config config.hardware-v2.yaml --domain electrical_safety --limit 6 --format text

### 5.7 信号完整性问题

    & $RagPython -m ddr_rag search "眼图的张开程度受到哪些抖动和阻抗因素影响？" --config config.hardware-v2.yaml --domain signal_integrity --limit 6 --format text

## 6. 怎样阅读 search 输出

单条检索结果通常形如：

    [C1] score=...
    文档 ID | 版本 | 资料类别 | PDF 第 N 页
    domains: ...
    topics: ...
    section: ...
    source: ...

| 字段 | 含义 |
|---|---|
| [C1]、[C2] | 本轮查询中的证据编号；下一次查询会重新编号。 |
| score | 本轮结果的相对检索排序分数，不等于答案正确率。 |
| 文档 ID | 资料唯一标识，可用于 --doc-id 精确限定。 |
| 版本 | 文档修订版；工程结论必须考虑版本。 |
| domains / topics | 该段正文的最终分类。 |
| section | 原始资料章节标题。 |
| PDF 第 N 页 | 原文件回查定位。 |
| source | 本地原始资料路径。 |

工程签核、具体数值、引脚、封装、时序和复杂表格必须回看原始 PDF，而不是只依赖检索摘录。

## 7. 第三步：使用 DeepSeek 组织答案

ask 会先本地路由和检索，然后将问题及有限证据提交给 DeepSeek，再在本地验证模型给出的 [C#] 引用。

当前项目根目录 .env 已存在，且 DEEPSEEK_API_KEY 已配置；日常无需重新填写。不要将真实 Key 写入 YAML、Markdown、命令输出、截图或提交到版本库。

示例：

    & $RagPython -m ddr_rag ask "GW2A 的 VCCX 与 VCCIO 上电顺序和滤波要求是什么？" --config config.hardware-v2-online.yaml --domain power_management --part GW2A --limit 6 --format text

在线执行流程：

    本地确定领域
      → 本地 Hybrid 检索
      → 发送问题和有限证据给 DeepSeek
      → 生成含 [C#] 的答案
      → 本地验证引用编号
      → 输出答案与“答案来源”

### 7.1 ask 会外发什么

会发送：

- 本轮问题。
- 最多 6 条本地检索命中的证据正文。
- 每条证据的资料名称、版本、章节、页码等来源元数据。

不会发送：

- 整个知识库。
- 整份 PDF 或 PPTX。
- 全量索引、向量数据库或模型文件。
- 评测题的标准答案或 expected_key_facts。
- API Key。

若只希望看资料、不希望任何信息外发，请始终使用 search 和 config.hardware-v2.yaml。

## 8. 可用领域和筛选条件

### 8.1 领域名称

--domain 后必须使用下表中的英文名称：

| 中文含义 | 参数值 | 主要内容 |
|---|---|---|
| 内存与 DDR | memory | DDR2/3/4/5、LPDDR、DDR 设计、布线、电源 |
| 高速接口 | high_speed_interface | USB、SATA、PCIe、HDMI、SGMII、CSI |
| 电源管理 | power_management | LDO、电源轨、上电时序、电源完整性 |
| 电气安规 | electrical_safety | 电气间隙、爬电距离、绝缘、高压 PCB |
| 信号完整性 | signal_integrity | 阻抗、端接、眼图、抖动、SI |
| 通用硬件 | hardware_general | 原理图、管脚、配置、PCB 通用设计 |

跨领域问题必须显式重复 --domain，例如：

    & $RagPython -m ddr_rag search "电源噪声如何影响高速信号质量？" --config config.hardware-v2.yaml --domain power_management --domain signal_integrity --limit 6

跨领域时 --limit 不能小于领域数量。

### 8.2 其他筛选参数

| 参数 | 作用 | 示例 |
|---|---|---|
| --topic | 限定主题，可重复 | --topic ldo、--topic impedance |
| --memory-type | 限定内存类型 | --memory-type DDR3 |
| --interface | 限定接口 | --interface pcie |
| --part | 限定器件型号 | --part GW2A、--part RK3568 |
| --doc-id | 只搜索一份资料 | --doc-id GOWIN_UG206_GW2A_GW2AR_SCHEMATIC_GUIDE_V1_9_3 |
| --limit | 最多返回或提交的证据数 | --limit 6 |
| --format | 人工阅读或程序处理 | --format text / --format json |

支持的 --memory-type：DDR2、DDR3、DDR3L、DDR4、DDR5、LPDDR3、LPDDR4、LPDDR4X、LPDDR5、LPDDR5X。

支持的 --interface：usb、sata、pcie、hdmi、sgmii、csi。

## 9. search 的三种检索模式

search 默认使用 hybrid，通常不必手动指定。

| 模式 | 参数 | 合适的场景 |
|---|---|---|
| 混合检索 | --mode hybrid | 默认推荐；同时利用语义和关键词。 |
| 语义检索 | --mode dense | 中英文术语不一致、以概念描述问题时。 |
| 关键词检索 | --mode sparse | 精确型号、引脚、寄存器名、数值、术语检索时。 |

例如查精确电源名称：

    & $RagPython -m ddr_rag search "VCCX VCCIO" --config config.hardware-v2.yaml --domain power_management --mode sparse --limit 6

例如查询抽象概念：

    & $RagPython -m ddr_rag search "稳压器输入接近输出时为什么不能维持稳定输出？" --config config.hardware-v2.yaml --domain power_management --mode dense --limit 6

## 10. 怎样把问题问得更准确

不够明确的问题：

    这个怎么布线？

它没有给出器件、信号、接口、内存类型或目标约束，系统很可能要求澄清。

更好的问题：

    GW3A-20 外接 DDR3 时，时钟差分对的拓扑、阻抗和等长要求是什么？

其中已经给出了：

- 型号：GW3A-20。
- 内存类型：DDR3。
- 对象：时钟差分对。
- 目标：拓扑、阻抗和等长。

对应命令应增加：

    --domain memory --memory-type DDR3 --part GW3A-20

多子问题建议逐项拆开检索。例如不只问“电源要求”，而是分别查询上电顺序、去耦和滤波。当前在线生成已通过引用和拒答验收，但已知个别复合问题可能漏述一个细节；重要设计事项需要检查每个子问题是否都有证据支持。

## 12. 首次检索为什么较慢

第一次执行 search 或 ask 时，程序需要启动 Python、加载 PyTorch、从 D 盘载入 BGE-M3、打开本地 Qdrant/BM25 索引，并计算问题向量。因此首次可能等待几十秒，部分机器约接近 90 秒。

出现 Loading weights 时通常表示模型正在加载，不是死机。route 不加载模型，一般会明显更快。

当前 CLI 是“一条命令一个进程”，每一次新的 search 或 ask 都可能重新加载模型；项目尚未提供常驻式网页聊天服务。

## 13. 常见问题

### 13.1 找不到 ddr-rag

不要直接输入 ddr-rag。使用：

    & $RagPython -m ddr_rag --help

### 13.2 PowerShell 提示 $RagPython 不存在

关闭窗口后变量会失效。重新执行：

    Set-Location D:\pcb\AI_PCB
    . .\scripts\use_d312_env.ps1
    $RagPython = ".\.venv-d312\Scripts\python.exe"

### 13.3 中文乱码

执行：

    $env:PYTHONIOENCODING = "utf-8"

环境入口脚本正常情况下已经设置该变量。

### 13.4 route 返回 clarification_required

补充 --domain。这通常是范围保护机制，不代表资料缺失。

### 13.5 搜不到想要的内容

按以下顺序尝试：

1. 明确写出型号、接口、信号名称和内存类型。
2. 显式增加 --domain。
3. 使用 --part、--memory-type 或 --interface 限定范围。
4. 精确术语改用 --mode sparse。
5. 概念性描述改用 --mode dense。
6. 默认优先尝试 --mode hybrid。
7. 将复合问题拆成多个单独问题。
8. 确认目标资料已在 V2 目录登记。

### 13.6 ask 缺少 API Key 或被拒答

ask 才需要 .env 中的 DEEPSEEK_API_KEY。如果模型拒答、没有引用、出现伪造引用或答案为空，请先对同一问题执行 search，检查本地证据。不要关闭引用校验；证据不足时接受拒答或补充可靠资料。

## 14. 使用边界和工程审核

- RAG 的定位是快速定位资料、汇总可回查证据和减少翻阅时间，不能代替工程师最终审核。
- 当前主要理解正文、简单表格文字和图注；对原理图几何连接、箭头、纯图片拓扑和复杂表格列关系理解有限。
- 不同器件、封装、DDR 类型和版本的规则不能因为数值相似而直接互换。
- NXP 文档部分页面的解析状态为 partial_success；涉及其复杂表格、图片或具体数值时必须回看原 PDF。
- 信号完整性 PPT 是未审核培训资料，只能作为工程经验，不能替代原厂要求或标准。
- 对电压、电流、时序、阻抗、长度差、安规距离、引脚和封装等结论，必须以原始资料和实际项目条件完成签核。
