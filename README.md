# 通用硬件 RAG

面向硬件设计资料的本地优先检索与问答工具。它把已登记的 PDF、DOCX、PPTX 解析为可定位的证据片段，先在本地检索，再由用户决定是否调用 DeepSeek 生成带引用的回答。

例如，你可以问“GW2A 上电时序有哪些要求？”，先查看命中的原厂资料页码，再决定是否让模型基于这些证据作答。**回答只用于辅助查资料，不代替原厂文档核对和工程签核。**

> 本仓库主要提供程序、配置、资料目录元数据和评测题集。原始资料、模型缓存、生成的 Chunk/索引及本机 Python 环境没有提交到 Git；新机器克隆后不能直接检索现有 10 份资料。见下文「在另一台机器上复现」。

## 一分钟了解

- **当前主线：通用硬件 RAG V2。** 覆盖内存、高速接口、电源管理、电气安规、信号完整性和通用硬件六个领域；明确领域时可筛选，跨领域必须显式指定。
- **本地检索：** Docling 解析与结构化切分，BGE-M3 向量、Qdrant Local 和 BM25/RRF 混合检索；返回资料身份、版本、章节、页码/幻灯片等来源信息。
- **可选在线回答：** 只有使用在线配置执行 `ask` 等明确的回答操作，才会将问题和最多 6 条命中证据正文及来源元数据发送至 DeepSeek，并在本地校验引用。`search` 不调用回答 API。
- **兼容旧库：** 默认 `config.yaml` 仍指向冻结的 DDR V1.2；使用 V2 必须显式传入 V2 配置，不会暗中切换索引。

```text
已登记资料 → 解析/切分 → 本地 BGE-M3 + Qdrant/BM25
                              ↓
                       带来源的本地证据
                              ↓ 可选
                         DeepSeek 回答
```

## 本机快速使用

以下命令适用于**已经完成 D 盘环境和 V2 索引构建的这台机器**。在项目根目录打开 PowerShell：

```powershell
. .\scripts\use_d312_env.ps1
.\.venv-d312\Scripts\python.exe -m ddr_rag search "GW2A 上电时序有哪些要求？" --config config.hardware-v2.yaml --domain power_management --limit 6 --format text
```

第一行准备当前终端的本地缓存路径；第二行只检索、不调用 DeepSeek。若需要模型整理答案，先在本机 `.env` 中配置 `DEEPSEEK_API_KEY`，再明确运行：

```powershell
.\.venv-d312\Scripts\python.exe -m ddr_rag ask "GW2A 上电时序有哪些要求？" --config config.hardware-v2-online.yaml --domain power_management --limit 6 --format text
```

这一步会产生 API 请求和费用。在线配置与离线 V2 配置的关键区别是是否启用生成；**仅修改 YAML 不会自动调用 API**，实际执行 `search` 仍是本地检索。`route` 也只做本地范围判断，问题领域不明确时会要求澄清，且不会先调用回答 API。

不知道筛选参数时，先用自然语言提问；确定范围后再加 `--domain`、`--part`、`--memory-type` 等。不要猜测 Chunk 名称，Chunk 是程序自动生成的证据单元。完整示例与筛选建议见[使用说明](项目说明文档/使用说明.md)和[筛选条件](项目说明文档/筛选条件.md)。

## 在另一台机器上复现

本仓库不是可直接运行的完整知识库发行包。`.gitignore` 排除了原始资料、模型/运行缓存、解析结果、Chunk、向量与索引、报告及虚拟环境；部分原文可能受第三方许可或再分发限制，不能因为代码已上传就假定可以一并上传或共享。

复现顺序是：

1. 准备 Windows x64、Python 3.12 和项目依赖；当前配置的 BGE-M3 固定使用 `cuda:0`，已验证环境为 NVIDIA RTX 4060 + CUDA PyTorch。CPU 向量化回退尚未验收。
2. 在本地创建虚拟环境并安装 `pyproject.toml` 中的依赖，以及与显卡匹配的 PyTorch；下载 BGE-M3 和解析所需模型/编码缓存。`scripts/use_d312_env.ps1` **不会创建环境**，只在现有 `.venv-d312` 上设置当前终端变量。
3. 合法取得资料原件，放到 `data/catalog/hardware_v2_documents.yaml` 所登记的相对路径，并核对版本与哈希。目录元数据不等于原文；缺少原文就不能重建完整 V2 索引。
4. 用 `config.hardware-v2.yaml` 校验目录，再执行解析、切分、Embedding 和索引构建；完成后先运行本地测试与 `search`，确认来源定位正常，再按需配置在线回答。

目前没有面向全新机器的一键安装/一键下载脚本；模型与资料准备是实际前置条件。不要把现有机器的 `D:\pcb\AI_PCB` 路径原样用于别人的环境；`.env.example` 中的项目路径是本机示例，复制后应按实际位置修改或移除。真实 `.env` 和 API Key 不得提交。项目也尚未附加软件许可证；分享或复用代码前应明确授权方式。

## 能做什么，不能做什么

- 普通问题按确定的单一领域检索；跨领域查询需重复指定 `--domain`。资料类别与来源身份会随证据返回，未审核培训材料不能当作原厂规范。
- PDF、DOCX、PPTX 可作为输入，但当前主链路依赖**可解析的文字、简单表格和图注**；纯图片、复杂表格/拓扑关系可能缺失或错位。关键引脚、数值和图示必须回看原文。
- 不做 OCR、图片理解、自动监视目录、Web/EDA/PCB 设计文件操作，也不自动判断工程结论是否适用于你的器件版本和板级条件。
- 评测里的引用覆盖率衡量“是否引用了预期来源”，不等于回答完整性。已知有 7/36 道在线可回答题漏述部分预期要点，见[改进方向](项目说明文档/改进方向.md)。
